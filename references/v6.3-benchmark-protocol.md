# Algolia Mobile Home — Benchmark Protocol v2 (frozen pre-registration)

> **상태: 다음 실험을 위한 평가 계약 초안.** 실행 전 실험자가 확정·해시 저장해야 한다. 실제 Figma 직접 관측이 없으면 해당 항목은 UNKNOWN으로 남기고 벤치마크 품질 PASS를 금지한다.

## 1. 목적을 두 개로 분리

**Track I — Implementation Fidelity:** 같은 모바일 Home을 구현했을 때 Figma에 얼마나 정확히 일치하는가?

**Track II — QA Detection Capability:** 같은 오류가 심어진 Vue Home을 받았을 때 스킬이 얼마나 많은 오류를 정확히 발견하고 해결하는가?

이 둘은 독립적으로 평가한다. A/B/C의 구현 결과가 서로 다르면 스킬의 '검수 능력'만을 독립적으로 평가할 수 없다. Track II는 **동일한 오류 주입 fixture**에서 실행한다.

## 3. 테스트 A/B/C

| 그룹 | 구현 Track I | 검수 Track II | 제한 사항 |
|---|---|---|---|
| A | Sol 단일 역할, 스킬 없음 | 같은 고장난 fixture, 보편적 수동/모델 검수 | 역할별 API 세션 분리는 단일 연속 세션과 다르므로 프로토콜 고정 |
| B | A와 같은 모델·설정, 스킬 적용 | 같은 fixture + 스킬 검증기 | A와 동일한 원본·개발 환경 |
| C | 균형형 멀티 역할(모델·호스트 명시) | 같은 fixture + 역할별 교차 검증 | 실제 subagent 병렬인지 host-mediated context인지 구분하고 총 비용 기록 |

**중요:** Track II의 Gold 오류 목록은 검사 대상 모델과 Fixer에게 제공하지 않는다. 독립 평가자는 정답을 보유해 TP/FN/FP를 계산한다. A/B/C에 도구 제약이 다르면 같은 시험이라고 주장하지 않는다.

### 실행 조건

1. **무료 Preflight**: Figma의 실제 선택 가능한 레이어·Properties 읽기, Node 및 Playwright, 서버 실행, API 접근·요금 파악.
2. **Gold Freeze**: Figma 측정/스크린샷, 표준 텍스트, 레이어 인벤토리, 평가 assertion, 해시 고정. 출처 미확인 항목은 `UNVERIFIED`.
3. **A/B Pilot**: 동일한 조건에서 최소 1회씩 실행. API usage와 원문 응답을 선저장하며 수행.
4. **C Optional**: A/B와 품질 측정을 비교할 수 있는 여유 예산이 있고, 멀티 역할 실행 경로가 재현 가능할 때만 수행. 예산 부족시 NOT_RUN.
5. **반복**: 엔진과 예산 검증을 통과한 뒤 조건당 3회 목표; $5로 부족하면 반복 횟수 감소 및 **탐색적 결과**로 보고. `n=1`에서 통계적 우위를 선언하지 않는다.

## 3.1. 검증기 확장 시 반드시 채워야 하는 67개 항목

기존 고정 150개에서 평가불가로 분류된 속성은 정확히 `fill 13 / gap 13 / font·size·weight·line_height·letter_spacing 30 / text 6 / radius 2 / child_count 2 / padding 1`이다. 확장 구현은 같은 ID와 기대값을 보존한 상태에서 지원 여부를 개선하고, 사후에 검사 항목 자체를 바꿔 점수를 올리지 않는다. 실제 원본 근거가 부족하면 해당 항목을 그대로 NOT_EVALUABLE로 남긴다.

## 4. 판정 용어 정의

| 상태 | 의미 | 집계 |
|---|---|---|
| `MATCH` | 직접 확인한 원본 값과 실제 DOM 값이 지정 허용오차 안 | 검증 성공 |
| `MISMATCH` | 같은 범위·환경에서 실제로 값이 다름 | 검증 실패 |
| `NOT_EVALUABLE` | 평가기 미지원 속성, 자산/원본 부재, 출처 불충분 등 | **분모에 남기고 커버리지 손실** |
| `BLOCKED` | Figma/앱/브라우저/API 기능 자체 접근 불가 | 실행 차단, 전체 PASS 불가 |
| `NOT_RUN` | 예산/일정/접근 문제로 계획한 실험 미실행 | 비교 결과 없음 |
| `PARTIAL` | 일부 값 측정됐지만 필수 평가·단계·독립 검수 미완료 | 전체 PASS 금지 |
| `VERIFIED_RECORDED_SCOPE` | 사전 지정 범위·증거·평가 조건 충족 | **해당 범위**의 검증 근거일 뿐 모든 제품 상태 보증 아님 |

### KPI 계산 (각각 반드시 숫자 보고)

- `Evaluable coverage = (MATCH + MISMATCH) / frozen assertion count`. **이전 83/150=55.33%**.
- `Observed match ratio = MATCH / (MATCH + MISMATCH)`; 분모가 0이면 N/A. 이전은 83/83=100%였으나 **설계 전체 품질 점수로 사용 금지**.
- `Total verified ratio = MATCH / frozen assertion count`; 이전은 83/150=55.33%. 평가불가를 제외한 점수를 대표 성능으로 쓰지 않음.
- `Mutation recall = TP / (TP + FN)`, `Mutation precision = TP / (TP + FP)`; 의도적 결함 20개 + 무변형 정상 fixture로 측정. TP=정답 결함 정확히 발견, FP=정상 항목 잘못 보고, FN=실제 결함 놓침.
- `Fix success = confirmed fixed defects / attempted fixes`. 수정 결과는 독립 evaluator가 전/후 같은 조건에서 재확인해야 인정.
- `Total cost = all API generations + cache reads/writes + tool/count charges (known) + retries + failed calls`. 금액 미확인 항목은 `UNKNOWN_CHARGES`로 분리하고 비교 한계를 보고.
- `Cost per confirmed fixed defect = total cost / confirmed fixes`. 확인 수정 0이면 N/A, 0달러로 표기 금지.
- `Elapsed time`: 벽시계 초; `requests`: 전체 API 호출 수, 성공/실패/중단을 별도 집계.
- `Completion rate`: 사전 고정 단계 중 증거가 존재하고 PASS한 단계의 비율. C가 중단되면 최종 품질 PASS 아님.

## 5. 합격 기준 (v6.3 개발 목표)

### 필수 게이트

| Gate | 최소 기준 | 실패 시 |
|---|---|---|
| G0 권한 | Figma 직접 속성 확인과 앱 실제 브라우저 접근 성공 | `BLOCKED`, 비용 사용하는 품질 벤치마크 시작 금지 |
| G1 증거 | 모든 중요한 검사에 Figma/DOM 출처·동등 상태·해시, 사전 고정 Gold | 불명확한 항목 UNKNOWN, 전체 PASS 금지 |
| G2 측정 가능률 | **≥95%**의 frozen assertions 평가 가능. 150개 기준 **143개 이상**; 중요 항목 `NOT_EVALUABLE=0` | `PARTIAL` |
| G3 수치 정확도 | Geometry/실제 Gap **±1 CSS px** 기본, font family/weight/size/line-height/문구는 원본 지정값/줄 수와 일치, 색상 토큰 정규화 후 일치 | 불일치 MISMATCH (유효한 예외는 사전 등록) |
| G4 콘텐츠/에셋 | 주요 영역·버튼·아이콘·이미지 누락 **0개**, placeholder를 실제 디자인 자산 일치로 처리 금지 | P0 결함이면 FAIL |
| G5 결함 탐지 | 20개 고정 Mutation과 **최소 20개 무변형 정상 대조항목**에서 **Recall ≥90%(18/20)**, **Precision ≥90%**, P0 결함 **전부 검출** | 검증기 출시 기준 미달 |
| G6 기능/안정성 | Home 클릭/스크롤/overflow/런타임 예외 필수 시나리오 PASS; 원본 없는 폭은 반응형 안정성만 주장 | 기능 검증 `PARTIAL` |
| G7 멀티 역할 | C는 필요한 단계의 실제 증거와 최종 게이트·별도 검수 완료 | C 결과 `PARTIAL`; 비용 비교는 가능, 완결 품질 비교 금지 |
| G8 비용/저널 | A/B/C 및 사전/재시도 포함 누적 예약 예산 ≤$5; usage 있는 모든 요청의 원문/에러/저널 보존 | 신규 유료 호출 차단·복구 후 재개 검토 |

수치 정확도 게이트는 **스킬의 QA 완료 선언에 필요한 기준**이고, 벤치마크 모델 A/B/C에 일률적으로 품질 PASS를 요구하는 것이 아니다. A/B/C는 실패하더라도 성능 관측값으로 보존한다.

### 우선순위

- **P0:** 주요 UI 영역/아이콘/에셋 완전 누락, 실제 Figma 접근 허위, 측정 근거 조작, 작업 중단 결과를 완료로 표시, 예산 상한 위반.
- **P1:** 실측 geometry/gap 오차, 폰트 불일치, 중요한 텍스트 줄바꿈, 반응형 overflow 등.
- **P2:** 이미지 안티앨리어싱·서체 렌더러에 따른 경미한 차이. 단, 측정 기준에 있는 값은 단독으로 면제하지 않음.

## 6. 독립 Gold 평가의 최소 품질

- 사전 고정 150개 비교 항목은 그대로 두고 **확장 속성**(색상/폰트/텍스트/gap/에셋/누락)을 지원하는 evaluator로 재평가. 버전업 후 비교 항목이 달라지면 `legacy150`과 `extended`를 별도 표로 보고.
- Figma 원본 측정 증거는 실제 파일을 보존하고, 첨부할 수 없는 경우 해시·증거 ID·접근 한계를 남김. 비공개 Figma 원본/사용자 세션은 공개 GitHub에 업로드하지 않음.
- 아이콘 윤곽과 이미지 자산은 DOM `width/height`만으로 통과하지 않음. 실제 SVG/path/asset 존재·로딩·스크린샷 비교가 필요.
- 영역별 시각 차이는 참고 근거이며 모든 이미지가 불일치하거나 원본 캡처가 없으면 **VISUAL_NOT_EVALUABLE**. 이미지 유사도 하나로 수치 오류를 면제하지 않음.
- 독립 검수는 실제 Figma에 직접 접근한 별도 reviewer일 때만 인정. 동일 모델이 재검사한 경우 `SECOND_PASS_ONLY`.

## 7. 비용 집계·회계 정책

- 사용자 승인 **실험 총 $5.00**. 모든 실험 합산 상한이며 $5 per A/B/C가 아님. 이전 리포트의 $10은 다음 실험에 승계하지 않는다.
- 요청 시작 전 `input_tokens_limit`, `output_tokens_limit`, caching 예상 비용, 동시 예약 요청 수로 **보수적 최대 비용** 예약. 이미 사용된 확정/추정 비용 + 모든 진행 중 예약 합계가 한도를 넘으면 새 호출 금지.
- HTTP 응답을 받으면 **원문/response ID/usage/시간/상태를 먼저 내구성 있게 저장**한 후 모델 명령을 파싱·검증한다. 예외가 나도 원문과 오류 사유를 보존한다.
- 응답 ID가 불명확한 실패 건을 자동 재발행하지 않는다. 응답이 존재할 수 있으면 사용자 승인 또는 provider 지원 상태 조회로 중복 과금을 방지한다.
- 캐시 쓰기/읽기/생성 및 제공자별 기타 비용은 서로 분리. 정확한 실제 청구액은 청구 화면 확인 전까지 추정으로 표기한다.
- 예산 게이트는 소프트웨어 차단이지 외부 서비스 청구를 법적으로/기술적으로 보증하지 않는다. 모르는 비용이 있으면 `COST_UNCERTAIN`으로 기록하고 다음 유료 호출을 막는다.

## 8. 최종 보고서 필수 표

1. 기준 디자인 프레임/뷰포트/에셋/폰트/Gold hash, 접근 성공 여부.
2. 그룹별 `A|B|C`, `COMPLETE/PARTIAL/NOT_RUN`, 모델 ID·역할·도구·추론 설정, 총 호출 수·사용량·비용.
3. Legacy 150: MATCH / MISMATCH / NOT_EVALUABLE, evaluable coverage, total verified ratio. 확장 검사 결과도 분리.
4. 필수 영역별 실제 수치 오차·자산/텍스트 누락·반응형/기능 검사 결과.
5. Mutation TP/FP/FN, recall/precision, P0 누락 여부.
6. C의 최종 독립 검수 완료 여부 및 단계별 증거. 실패한 API 요청과 복구 가능성.
7. **어떤 기준을 충족하지 못했기 때문에 PASS가 아닌지**와 다음 실험에서 수집할 근거.

## 9. 승인 가능한 결론의 범위

- A가 $0.1775, B가 $0.2605, C가 $0.4238이었다는 **이번 1회 실행 비용 추정 차이**는 말할 수 있음.
- 이번 실험의 UI 구현 품질 순위, 스킬의 비용 절감률, 멀티 역할의 평균 우월성은 아직 **말할 수 없음**(고정 evaluator 커버리지 55.3%, Figma 참조 불완전, n=1, C 중단).
- 다음 실험도 G0/G1/G2/G7을 통과하지 못하면 성능 우위 결론 대신 `INCONCLUSIVE`와 실제 수집된 숫자만 보고.
