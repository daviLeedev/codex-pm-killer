# v6.1: Evidence-bound QA reports and R15-derived safeguards

This supplements the v4/v5 verification gate and v6 orchestrator, **not a replacement**. The R15 report is a source of generalized risk patterns only; do not put customer screenshots, internal Figma links/IDs, routes, code or raw audit artifacts in this public repository.

## Evidence environments

- `REAL_APP_RUNTIME`: measured in the actual application route with actual router, global styles and component tree. Set API mode (LIVE or MOCKED); mocked endpoints cannot prove live backend flows.
- `ISOLATED_VUE_FIXTURE`: API-free standalone template/SCSS preview. Can demonstrate geometry regression but **cannot satisfy** a REAL_APP_VISUAL target.
- `SOURCE_ONLY`: static source inspection or compile; not runtime DOM verification.
- `LIVE_END_TO_END`: requires REAL_APP_RUNTIME and LIVE API evidence. Desktop Chromium cannot prove iOS Safari.
- Relative spacing matching at different viewport/frame heights does not establish full-frame pixel equality.

## Evidence trace

Every claim must cite its Figma source evidence and local runtime evidence by stable ID. Evidence hashes are SHA-256 digests of actual file bytes. For claims of identical source/local files, register *both* artifacts and their matching hash. A digest proves consistency with recorded bytes, **not** screenshot authenticity, access permissions, viewer inspection coverage or original file identity.

Keep evidence in the **application's private .design-qa folder** and do not publish it in the skill repository.

## Test failures

Never silently waive a failing test, even if outside the latest CSS diff. Classify every failure:
- `DESIGN_BASELINE_CONFLICT`: historical expected CSS value differs from current Figma baseline; do not alter test without direct reinspection.
- `DESIGN_MISMATCH`: directly measured geometry/visual behavior differs.
- `TEST_INFRASTRUCTURE`: missing jsdom, module import, build runner or environment failure.
- `BEHAVIOR_REGRESSION`: real application state, routing, auth or interaction regression.
- `UNKNOWN`: triage required; cannot pass.

Each failed test requires its impact and concrete follow-up; report zero unresolved failures before claiming full scoped PASS.

## Multi-agent evidence

A skill version string does **not** prove that a multi-agent workflow actually executed. Attach the existing v6 orchestrator state file and all per-role evidence, including ASSIGN/RECORD records and independent direct Figma reviewer capability. The checker compares recorded actors and hashes. A self-authored state cannot independently establish true identity, Figma browser access, or real parallel execution. When no direct independent reviewer exists, report PARTIAL, not a fictitious PASS.

## Usage

Start with `assets/v6-audit-manifest.template.json`, replace placeholders with **real measured data** and hash actual local files. Execute from the target project:

    node /path/to/codex-pm-killer/scripts/v6-audit-provenance.mjs --workspace "$PWD" --input .design-qa/example/audit-manifest.json --out .design-qa/example/audit-report.json

The script writes `audit-report.json` and `FOLLOW_UP.md`. Exit code 2 indicates PARTIAL, which must never be converted to PASS by editing the manifest without fresh evidence.

Final report should include measured comparison, runtime evidence grade, 1st/2nd reviewer status, test totals by category, explicit open blockers, and follow-up actions. Preserve earlier failures and why they were missed. Validate the *original* v4/v5 outputs separately.
